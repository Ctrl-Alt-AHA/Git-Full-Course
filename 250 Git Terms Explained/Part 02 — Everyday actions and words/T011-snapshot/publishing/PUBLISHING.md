## Patreon

Git snapshots: understanding a whole recorded version

Imagine a recipe website with a title, menu, and photo. When you record a title change, the next snapshot still describes the unchanged menu and photo. A commit points to the tracked file versions chosen for that commit, so the recorded state makes sense as a whole.

This is a logical snapshot, not a screen image or an entire disk copy. Git can reuse unchanged content internally. Untracked files are outside the recorded state.

Takeaway: changes tell you what differs; a snapshot tells you what was there.
